# Native decode numerical identity gate

Frozen before first natural-fixture execution of this GPU path, 2026-10-04.
This separate 3600-second process guard does not extend any closed study.
It is a correctness gate, not a performance benchmark. No source/precision,
seed/bin/quota/subset change is permitted after reading its outputs; a failed
identity must be preserved and a changed operator needs a separate protocol.

Use the first eligible complete development article at 512 and 2048 tokens,
all final seeds17/29/43, binary(4,4), ternary(3,2), coarsened binary depth//2,
the pinned360M model's original BF16 Q/K/V and output projection. Original
physical KV has five heads; query/metadata has15 heads, grouped by three.
Verify selected input files by the already independently audited immutable
parent manifest; do not refit or read any new quality-test text.

At every position, encode the actual single query and physical key expanded
to the learned fifteen-head bridge with FP32 batched add-matrix products,
TF32 disabled, then the unchanged FP64 PCA/quantile book, right-inclusive
duplicate cutpoints and reverse base-prime digits. Both complete query/key
code arrays must equal the archived block-path codes exactly. Latent FP32
differences are reported; they do not excuse a changed address. For every
position and each of the nine seed/finite recipes, GPU shell histograms,
exact twice-midranks, three-head sums and unique integer score/timestamp top-k
must equal all archived group masks: 115200 rows in total. All earlier128
positions retain their full causal prefix; later positions retain exactly128
including recent8. Four separate synthetic tests cover pairwise independently
defined ranks, all ties/empty/early cases, duplicate thresholds and physical-GQA
single-query causality, on CPU and CUDA.

For each context choose queries at prefix lengths L/2,3L/4,L, last query in
each prefix. Run stock dense, recency, uniform and all nine finite readouts:
72 one-query outputs in total. Physically gather one shared K/V list per group
and enforce the same PyTorch SDPA backend for all paths. Try forced
FLASH_ATTENTION on both lengths and on dense/128-key shapes; if any probe is
unsupported, record all probe errors and use forced MATH for all paths.
This fallback cannot establish optimized dense competitiveness. No backend
or implementation selection by observed runtime. dropout=0, enable_gqa=True,
is_causal=False since the supplied prefix is already causal.

Compare every head and projected output to an independently computed NumPy
FP64 softmax/readout on the same actual selected original BF16 vectors.
Before inspecting values, thresholds are head NRMSE<=0.01 and projected
NRMSE<=0.015; maximum absolute error for each must be <=0.03 times its FP64
reference maximum absolute value plus1e-4. These are component arithmetic
tolerances, not an NLL/non-inferiority gate and do not replace the closed
held-out operator. Preserve native BF16 output bits and FP64 references, all
codes, all per-readout errors, mismatch counts/examples and complete failures.

Snapshot executed source, exact protocol and selected input hashes; capture
Torch/CUDA/device/backend/environment. Do not record per-method performance
samples here. Only the separate process-wall guard is recorded. Passing
permits preparation of a separately frozen cost benchmark including current
query/key encoding, code update, routing, physical gather, SDPA and output
projection. No native efficiency, complete-model decode, cache eviction,
pretraining independence or universal-prime conclusion follows from this gate.
